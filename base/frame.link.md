# base.frame.link

## Kubernetes: Service와 Endpoint (네트워크 위상에서의 심링크)
쿠버네티스에서 심볼릭 링크의 철학을 가장 완벽하게 구현한 것은 **Service** 객체입니다.

* **물리적 경로 (Target):** 수시로 생성되고 죽는 파드(Pod)들의 실제 IP 주소들.
* **링크 경로 (Symlink):** Service가 제공하는 고정된 `ClusterIP`와 DNS 네임 (`my-svc.default.svc.cluster.local`).
* **동작 원리:** 클라이언트는 무조건 '링크(Service)'만 바라봅니다. Service는 내부적으로 Label Selector를 통해 실제 Pod IP(Endpoint)들을 가리킵니다.
* **Detach 메커니즘:** 특정 Pod를 트래픽에서 제외(Detach)하고 싶을 때, Pod를 죽일 필요 없이 해당 Pod의 Label만 변경하면 Service의 Endpoint 목록에서 즉시 제거됩니다. 물리적 실체(Pod)는 그대로 살아있어 디버깅이 가능하지만, 논리적 연결(Link)은 완벽히 차단됩니다.

## Docker: Bind Mount와 Image Tag (컨테이너 및 배포 위상)
도커에서는 볼륨(Volume)과 이미지 태깅(Tagging) 시스템에서 이 구조를 찾을 수 있습니다.

* **Volume / Bind Mount:**
    * **물리적 경로:** 호스트 OS의 실제 디렉토리 (`/var/data`).
    * **링크 경로:** 컨테이너 내부의 디렉토리 (`/app/data`).
    * **동작 원리:** 컨테이너는 내부 경로만 조작합니다. 컨테이너를 삭제(Detach)해도 호스트의 물리적 데이터는 완벽히 유지됩니다. 새로운 컨테이너를 띄우며 다시 링크를 맺을 수 있습니다.
* **Image Tags (`latest`):**
    * **물리적 경로:** 이미지의 고유한 불변 해시값 (`sha256:8b4c...`).
    * **링크 경로:** 사람이 읽을 수 있는 태그 (`nginx:latest`).
    * **동작 원리:** `latest` 태그는 그저 특정 해시를 가리키는 포인터입니다. 태그를 지우거나 다른 해시로 옮겨도, 원래의 이미지 레이어(물리적 데이터)는 삭제되지 않습니다.

## Linux Kernel: Mount Namespace와 Veth Pair (OS 커널 위상)
리눅스 커널 레벨에서는 파일시스템과 네트워크 구역에서 이 개념이 깊게 적용됩니다.

* **`mount --bind` (바인드 마운트):**
    * 특정 디렉토리 트리를 다른 위치에 그대로 투영합니다. 원본 경로와 마운트된 경로 양쪽에서 데이터에 접근할 수 있으며, `umount` 명령으로 연결을 끊어도(Detach) 원본 데이터는 전혀 영향을 받지 않습니다. (심링크와 달리 커널 레벨에서 VFS(Virtual File System) 노드를 직접 매핑하므로 더 강력한 결합입니다.)
* **Veth (Virtual Ethernet) Pair:**
    * **물리적/논리적 구조:** 네트워크 네임스페이스를 연결하는 가상의 랜선입니다. 한쪽 끝은 호스트의 브릿지(물리적 네트워크 장비 역할)에, 다른 쪽 끝은 컨테이너 네임스페이스 안에 둡니다.
    * **Detach 메커니즘:** 컨테이너를 네트워크에서 고립시키고 싶을 때, 컨테이너 내의 프로세스를 죽일 필요 없이 Veth 인터페이스의 연결만 끊어버리면 완벽하게 논리적 격리(Air-gap)가 성립됩니다.

## Python: Namespace와 Module Resolution (언어 런타임 위상)
파이썬 자체가 본질적으로 이름(Name)과 객체(Object)를 분리하는 **거대한 심볼릭 링크 엔진**입니다.

* **변수 바인딩 (`Variables as Labels`):**
    * 파이썬의 변수 `a = [1, 2, 3]`에서 `a`는 메모리 공간이 아니라, 힙 메모리에 존재하는 리스트 객체(`[1, 2, 3]`)를 가리키는 이름표(Link)일 뿐입니다.
    * `del a`를 수행하면 데이터가 지워지는 것이 아니라, 현재 네임스페이스에서 **링크(이름표)만 Detach** 됩니다. 객체 자체는 가비지 컬렉터(GC)에 의해 처리될 때까지 메모리에 물리적으로 유지됩니다.
* **`sys.modules`와 `.pth` (모듈 경로 분석):**
    * 파이썬이 모듈을 `import`할 때, `sys.path`와 `.pth` 파일을 참조하여 물리적 파일 경로를 논리적 모듈 구조로 투영합니다.
    * 런타임에 `sys.modules['target'] = mock_module` 처럼 덮어씌우면(Symlink Swap), 기존 물리적 모듈 코드는 건드리지 않은 채 실행 컨텍스트 내에서의 논리적 흐름만 다른 곳으로 우회시킬 수 있습니다. 필요 시 해당 키를 지워버리면 다시 원래 상태로 Detach 됩니다.
